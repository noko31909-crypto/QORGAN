# Как запустить весь проект и протестировать все функции

Пошаговая инструкция: установка, запуск бэкенда и приложения, проверка каждой функции.

---

## Требования

- **Python 3.9+** (для бэкенда)
- **Flutter SDK** (для мобильного приложения)
- **Устройство:** симулятор/эмулятор или реальный телефон в одной сети с компьютером

---

## 1. Один раз: установка

### 1.1 Зависимости бэкенда

```bash
cd apps/backend
pip3 install -r requirements.txt
cd ../..
```

### 1.2 Зависимости приложения

```bash
cd apps/mobile
flutter pub get
cd ../..
```

### 1.3 IP-адрес для приложения

Если тестируете на **реальном устройстве**, приложение должно стучаться на IP вашего компьютера:

1. Узнайте IP (на Mac: **Системные настройки → Сеть** или `ifconfig | grep "inet "`).
2. В проекте замените адрес в двух файлах на ваш IP:

**`apps/mobile/lib/services/api_service.dart`** — строка с `baseUrl`:
```dart
static const String baseUrl = 'http://ВАШ_IP:5001/api';
```

**`apps/mobile/lib/services/socket_service.dart`** — строка с `serverUrl`:
```dart
static const String serverUrl = 'http://ВАШ_IP:5001';
```

На **эмуляторе** можно оставить `127.0.0.1` или `localhost` (на Android-эмуляторе для доступа к ПК часто используется `10.0.2.2:5001` — подставьте его в оба файла).

### 1.4 Модель детекции (опционально)

- Детекция оружия с камеры работает, если есть YOLO-модель: **`models/best.onnx`** (в корне репозитория).
- Если файла нет, при запуске бэкенда может быть ошибка загрузки модели. Остальные функции (авторизация, SOS, уведомления, карта, симуляция алерта) работают без модели — для них можно использовать **симуляцию** алерта (см. ниже).

## 2. Запуск всего проекта

### Вариант A: один скрипт (бэкенд + приложение)

```bash
./scripts/start_app.sh
```

Скрипт поднимает бэкенд на порту 5001 и запускает `flutter run`. Остановка: `Ctrl+C` (сначала остановится Flutter, бэкенд может остаться в фоне — при необходимости завершите процесс на порту 5001).

### Вариант B: вручную в двух терминалах

**Терминал 1 — бэкенд:**

```bash
cd apps/backend
python3 app.py
```

Должно появиться что-то вроде: `Running on http://0.0.0.0:5001`. Оставьте терминал открытым.

**Если пишет «Address already in use» / «Port 5001 is in use»:** порт занят старым процессом. Освободить порт (на Mac/Linux):
```bash
lsof -ti :5001 | xargs kill
```
После этого снова запустите `python3 app.py`.

**Терминал 2 — приложение:**

```bash
cd apps/mobile
flutter run
```

Выберите устройство (Chrome, симулятор iOS/Android или подключённый телефон). После сборки откроется приложение.

### Ошибка на macOS: «No developer tools were found» (xcode-select)

Если при `flutter run` появляется сообщение про **xcode-select** и отсутствие developer tools, возможны два варианта.

**Вариант 1 — поставить Xcode Command Line Tools (нужно для iOS-симулятора и сборки под iPhone):**

В Терминале выполните:

```bash
xcode-select --install
```

Откроется окно установки — нажмите «Установить» и дождитесь окончания. После этого снова выполните `flutter run`.

**Вариант 2 — запустить приложение в браузере (без Xcode):**

Запуск в браузере не требует Xcode.

- **Chrome / Edge:**  
  `flutter run -d chrome` — приложение откроется само.

- **Safari (или любой другой браузер):**  
  ```bash
  cd apps/mobile
  flutter run -d web-server
  ```  
  В терминале появится ссылка вида `http://localhost:XXXX`. Откройте её в Safari (или другом браузере).

Для теста API и бэкенда любого из вариантов достаточно.

**Если выбрали «macOS» и видите ошибку про xcodebuild:** для цели «macOS» нужен полный **Xcode** (из App Store). Проще запустить в браузере: `flutter run -d web-server` и открыть указанный localhost в Safari.

## 3. Проверка, что бэкенд жив

В браузере или через curl:

```bash
curl http://127.0.0.1:5001/api/health
```

Ожидается: `{"message":"School Safety API is running","status":"ok"}`.

Если бэкенд не запускается из‑за отсутствия модели, см. раздел **«Запуск без модели»** в конце файла.

## 4. Тестирование функций по шагам

### 4.1 Регистрация и вход

1. В приложении: **Create a new account**.
2. Заполните: Email (или телефон), пароль (не короче 8 символов), **School code** (например `SCH-1234`), **Role** — Guard или Student.
3. Нажмите **Create account** — должны попасть на главный экран.
4. Выйдите (если есть в UI) или переустановите/очистите данные и войдите: **Log in** → те же email и пароль, при необходимости School code.

**Проверка:** после входа виден главный экран с карточками (Live, SOS, Map, Notifications).

---

### 4.2 SOS

1. Откройте вкладку **SOS**.
2. Нажмите большую красную кнопку.
3. Должен отправиться запрос на бэкенд и появиться диалог об успешной отправке (и при наличии разрешений — геолокация уйдёт в инцидент).

**Проверка:** в бэкенде в логах или в БД появляется инцидент типа `sos_alert`.

---

### 4.3 Уведомление об оружии (симуляция, без камеры)

Смысл: проверить, что при «теракте» приходит уведомление, диалог и точка на карте.

1. Убедитесь, что бэкенд запущен и вы **залогинены в приложении** (лучше под пользователем с ролью **Guard**, чтобы создавались уведомления).
2. В **другом терминале** выполните:

```bash
python3 scripts/test_alert.py
```

или вручную:

```bash
curl -X POST http://127.0.0.1:5001/api/test/simulate-weapon-alert \
  -H "Content-Type: application/json" \
  -d '{"description":"Test: Knife detected","location":"Main Hall","confidence":0.95}'
```

3. В приложении:
   - Должен появиться **красный диалог** «Оружие обнаружено» (если приложение было открыто).
   - Откройте вкладку **Map** — должна отобразиться **точка угрозы** на карте и баннер «Опасность: Main Hall»; кнопка **«Что делать? Рекомендации»** открывает подсказки.
   - Откройте вкладку **Notifications** — у охранников появится запись об обнаружении оружия.

**Проверка:** диалог, маркер на карте, запись в уведомлениях.

#### Уведомление через реальную камеру (детекция в реальном времени)

Чтобы уведомление сработало от **реальной камеры** (веб-камера ноутбука или USB):

1. **Запустите бэкенд** (с моделью `models/best.onnx`):
   ```bash
   cd apps/backend
   python3 app.py
   ```
   В логе должно быть: `Started detection on camera 1` (или несколько камер). Если видите `Error: Could not open camera` или `Error reading frame` — камера не открылась (см. ниже).

2. **Разрешите доступ к камере** (macOS):
   - **Системные настройки → Конфиденциальность и безопасность → Камера** — включите доступ для **Terminal** (или для приложения, из которого запускаете `python3 app.py`).
   - Перезапустите бэкенд после включения доступа.

3. **Откройте приложение** и войдите под пользователем с ролью **Guard**.

4. **Направьте камеру на объект**, который модель умеет детектировать (оружие/нож по датасету обучения), или покажите **чёткое фото оружия/ножа на экране** перед веб-камерой. Модель обрабатывает каждый кадр; при уверенности **≥ 50%** срабатывает алерт.

5. В течение нескольких секунд:
   - в **терминале бэкенда** появится строка вида `WEAPON DETECTED: ...`;
   - в **приложении** — красный диалог «Оружие обнаружено»;
   - во вкладке **Notifications** — новая запись;
   - на **карте** — точка угрозы (локация камеры из БД, например «Main Entrance»).

**Важно:** Между срабатываниями для одной камеры стоит **cooldown 3 секунды** — повторный алерт не придёт раньше чем через 3 сек. Кадры с детекцией сохраняются в `data/detection_images/` (или в папке, заданной при запуске).

**Если камера не открывается:** убедитесь, что ни одно другое приложение не использует камеру (Zoom, FaceTime и т.п.), перезапустите бэкенд и снова проверьте доступ в настройках конфиденциальности.

---

### 4.4 Карта школы и рекомендации

1. Вкладка **Map**.
2. Без алерта: видны кнопка «Свободные выходы», легенда, подсказки по эвакуации.
3. После симуляции алерта (п. 4.3): красный маркер на карте, баннер «Опасность: …», кнопка **«Что делать? Рекомендации»** — открывается список советов (спрятаться, окно с 1 этажа, 112, SOS, тишина).

**Проверка:** маркер и текст «Избегайте это место», рекомендации открываются и читаемы.

---

### 4.5 First Aid и Lessons

1. На главном экране (Live) нажмите карточку **First Aid** или **Lessons**.
2. First Aid: поиск по симптомам/процедурам, список процедур (Control Bleeding, Dog Bite, CPR и т.д.), по нажатию — детали в нижней панели.
3. Lessons: поиск по видео, список уроков (Fire Safety, Lockdown и т.д.), по нажатию — описание и плейсхолдер видео.

**Проверка:** экраны открываются, список и детали отображаются.

---

### 4.6 School Safety (для охранников)

1. Войдите под пользователем с ролью **Guard**.
2. На главном экране откройте карточку **School Safety**.
3. Должны подгрузиться камеры (если есть в БД), отображаться плейсхолдер видео, переключатели (Location sharing и т.д.), кнопки Ambulance/Police, блок «Safe scale», при получении weapon_alert — обновление данных и диалог (если не перехвачен глобально на главном экране).

**Проверка:** экран открывается, при симуляции алерта (п. 4.3) данные обновляются.

---

### 4.7 Уведомления (список и «прочитано»)

1. Вкладка **Notifications**.
2. После симуляции алерта (п. 4.3) в списке должна быть запись (Today / Yesterday и т.д.).
3. Нажмите на запись — она помечается как прочитанная (визуально может измениться индикатор).

**Проверка:** список не пустой после алерта, нажатие помечает уведомление.

## 5. Краткая шпаргалка по командам

```bash
# Установка (один раз)
./scripts/setup.sh

# Запуск всего
./scripts/start_app.sh

# Или вручную:
# Терминал 1
cd apps/backend && python3 app.py

# Терминал 2
cd apps/mobile && flutter run

# Проверка бэкенда

# Симуляция алерта об оружии
python3 scripts/test_alert.py
# или
curl -X POST http://127.0.0.1:5001/api/test/simulate-weapon-alert \
  -H "Content-Type: application/json" \
  -d '{"location":"Main Hall","confidence":0.95}'
```

## 6. Запуск без модели YOLO (если бэкенд падает)

Если при `python3 app.py` возникает ошибка загрузки модели (например, `models/best.onnx` не найден):

- Либо положите обученную YOLO-модель в **`models/best.onnx`** (см. README проекта по датасету и обучению).
- Либо временно отключите инициализацию детекции: в `apps/backend/app.py` закомментировать создание `DetectionService`, автозапуск камер и установку колбэка `on_weapon_detected`; тогда работают только API (авторизация, SOS, уведомления, симуляция алерта через `POST /api/test/simulate-weapon-alert`). Детекция с камер в этом режиме недоступна.

## 7. Что и где тестировать (сводка)

| Функция | Где тестировать | Как проверить |
|--------|------------------|----------------|
| Регистрация / вход | Welcome → Create account / Log in | Успешный переход на главный экран |
| SOS | Вкладка SOS, красная кнопка | Диалог об отправке, инцидент в БД |
| Уведомление об оружии | Симуляция: `scripts/test_alert.py` или curl | Диалог в приложении, запись в Notifications |
| Точка угрозы на карте | Вкладка Map после симуляции алерта | Красный маркер, баннер «Опасность: …» |
| Рекомендации «что делать» | Map → «Что делать? Рекомендации» при активной угрозе | Открывается список советов |
| First Aid / Lessons | Главный экран → карточки First Aid, Lessons | Списки и детали открываются |
| School Safety | Вход как Guard → карточка School Safety | Экран с камерами и алертами |
| Список уведомлений | Вкладка Notifications | Записи после алерта, отметка «прочитано» |
| Детекция с камеры | School Safety + реальная камера + модель | При обнаружении оружия — алерт и уведомления |

После прохождения этих пунктов можно считать, что основные функции проекта запущены и протестированы.
