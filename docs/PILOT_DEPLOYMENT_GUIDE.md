# Qorgan: Руководство по развёртыванию пилота (1 сервер, 30 камер)

Это официальное руководство для инженеров по внедрению системы Qorgan. Документ описывает оптимальный процесс развёртывания пилотного проекта на одном мощном сервере для одновременной обработки до 30 камер.

---

## Часть 1: Требования к оборудованию

Для стабильной работы 30 камер на одном сервере требуется мощное железо.

| Компонент | Минимальные требования | Рекомендация (Production) |
|-----------|------------------------|---------------------------|
| Процессор | 8 ядер (Intel i7 / AMD Ryzen 7) | 16+ ядер (AMD EPYC / Intel Xeon) |
| Оперативная память | 16 GB | 32 GB RAM |
| GPU | Опционально | NVIDIA T4 / RTX 4060 (для ускорения) |
| Хранилище | SSD 256 GB | SSD 512 GB (для кэша видео) |
| ОС | Ubuntu 20.04/22.04 (Linux) | Ubuntu 22.04 LTS |
| Сеть | 1 Gbps | 10 Gbps (для приема 30 RTSP потоков) |

---

## Часть 2: Установка и настройка

### 2.1 Клонирование и установка зависимостей

Выполните следующие команды в терминале сервера:

```bash
# 1. Клонирование репозитория
git clone https://github.com/noko31909-crypto/QORGAN.git
cd QORGAN

# 2. Запуск скрипта установки зависимостей
./scripts/setup.sh
```

### 2.2 Настройка переменных окружения (Multi-Camera)

Для пилота на 30 камер используйте специализированный шаблон `.env`:

```bash
cp apps/backend/.env.multicam.example apps/backend/.env
nano apps/backend/.env
```

**Ключевые настройки для 30 камер:**

```env
QORGAN_PROFILE=centers
APP_ENV=production
SECRET_KEY=your_very_long_random_secret_key_here_at_least_32_chars
CORS_ALLOWED_ORIGINS=https://your-domain.com
DEMO_SEED=0
WS_API_KEY=your_websocket_secret_key
ENABLE_DETECTION=1

# Оптимизация для 30 камер
DETECTION_MAX_CAMERAS=30
DETECTION_MAX_WORKERS=8
DETECTION_FRAME_SKIP=2
DETECTION_MEMORY_LIMIT_MB=4000
DETECTION_FRAME_WIDTH=640
DETECTION_FRAME_HEIGHT=480

# Камеры
BOOTSTRAP_CAMERA_STREAM=rtsp://admin:password@192.168.1.100:554/stream
DEFAULT_SCHOOL_CODE=SCH-PILOT-01
```

### 2.3 Запуск сервера

Используйте подготовленный скрипт для запуска в продакшен-режиме:

```bash
./scripts/start_centers.sh
```

Сервер запустится на порту `5001`. Убедитесь, что порт открыт в firewall и доступен через обратный прокси (Nginx/Caddy) с HTTPS.

## Часть 3: Работа системы и управление камерами

### 3.1 Индивидуальное управление камерами

Главное преимущество новой архитектуры — камеры не запускаются все сразу при старте сервера. Охранник управляет ими сам через интерфейс:

1. Охранник заходит в веб-приложение.
2. Видит список всех 30 камер.
3. Нажимает кнопку `Start` напротив нужных камер (например, 5 входных дверей).
4. Сервер запускает детекцию **только для выбранных камер**.
5. Остальные 25 камер не потребляют ресурсы процессора.

**API для управления:**
- Запустить одну камеру: `POST /api/cameras/{id}/start`
- Остановить одну камеру: `POST /api/cameras/{id}/stop`
- Запустить пачку камер: `POST /api/cameras/batch-start` (Body: `{"camera_ids": [1, 2, 3]}`)
- Остановить все: `POST /api/cameras/stop-all`

### 3.2 Мониторинг ресурсов

Чтобы следить за нагрузкой на сервер, используйте новый endpoint:

```bash
curl -H "Authorization: Bearer <TOKEN>" http://localhost:5001/api/resources
```

Пример ответа:
```json
{
  "active_cameras": 15,
  "max_cameras": 30,
  "memory_mb": 2100,
  "memory_limit_mb": 4000,
  "cpu_percent": 45.2,
  "frame_skip": 2,
  "memory_pressure": false
}
```

**Что делать, если `memory_pressure: true`?**
Система автоматически увеличила пропуск кадров (frame skip) для защиты от зависания. Охраннику рекомендуется остановить часть камер, которые не используются в данный момент, через интерфейс или команду `stop-all`.

## Часть 4: Реакция на инциденты

Когда система обнаруживает оружие (ножи, пистолеты, топоры, скрытое оружие):

1. Кадр сохраняется в базу данных (в папке `data/detection_images/`).
2. Создаётся инцидент с типом `weapon_detected`.
3. Через WebSocket охранникам приходит мгновенное уведомление.
4. В интерфейсе появляется красный диалог: "Оружие обнаружено!".

**Действия охранника:**
- `Acknowledge`: Подтвердить, что увидел инцидент.
- `Resolve`: Закрыть инцидент (ситуация разобрана).
- `Mark FP`: Пометить как ложное срабатывание (если AI ошибся).

## Часть 5: Эксплуатация и обслуживание

### 5.1 Graceful Shutdown (Безопасное завершение)

При перезагрузке сервера система корректно освободит все ресурсы OpenCV и остановит потоки детекции без утечек памяти.

```bash
sudo systemctl stop qorgan-backend
```

### 5.2 Резервное копирование

Регулярно делайте бэкапы базы данных инцидентов:
```bash
cp apps/backend/instance/school_safety.db /backup/path/backup_$(date +%Y%m%d).db
```

### 5.3 Улучшение детекции скрытых предметов

Для детекции оружия в карманах и скрытых местах модель использует пониженные пороги площади (`min_concealed_area_ratio`). Если вы хотите переобучить модель (YOLO) на новые предметы (например, топоры, гранаты), подготовьте датасет и обучите модель, затем замените файл `models/best.onnx` и перезапустите сервер.
